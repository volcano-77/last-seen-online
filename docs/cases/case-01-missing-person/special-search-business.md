# 《寻人启事》特殊寻访业务与交叉证据设计

> 仅设计文档，尚未实现。剧情事实以 [story-bible.md](story-bible.md) 为准，证明依赖见 [information-dependency-map.md](information-dependency-map.md)，证据创建、保管与取得见 [evidence-artifacts.md](evidence-artifacts.md)。王曼取得材料的历史路径见 [wang-man-investigation.md](wang-man-investigation.md)。不修改代码、JSON、UI、现有网页或谜题实现。

## A. 正式业务流程

回声寻人网公开公益服务真实存在。“特殊寻访”不在公开服务列表，主要通过熟人介绍、老客户转介绍、私下联系或灰色关系转介进入。部分客户并不清楚梁所用方法；不能把全部公益业务或全部客户写成犯罪成员。

| 阶段 | 运作与输入 / 输出 | 后续可能留下的载体 | 能力与证据边界 |
| --- | --- | --- | --- |
| 1 私下委托 | 客户交目标姓名 / 昵称、旧照片、曾活动区域、关系说明和需要找人的说法；梁不严格核实叙述真伪 | 客户委托邮件、往来回复 | “失联 / 家属寻找 / 朋友寻找”不自动等于事实，不能只凭客户自述认定真实关系 |
| 2 建立特殊单 | 决定接单后建立稳定内部S编号 | 接单邮件、任务目录、工作表、客户沟通与交付材料 | 内部编号用于串联，不出现在所有公开寻人页，也不能推全部订单数 |
| 3 搜集公开资料 | 搜索、公开博客 / BBS / 校园网页、旧账号、公开照片和网友发帖 | 保存网页、搜索片段、工作材料中的来源 | 信息聚合为主，不靠黑客；发现旧信息不等于现在位置 |
| 4 公开寻人 / 众包目击 | 现有公开资料不足时，以表面合理寻人叙事发布或转发；善意网友给近期位置、单位、住区、见到时间 | 寻人页面历史副本、普通目击回复 | 网友不知道真实私下委托，回复是未经核验的输入；这是核心灰色定位手段，不要求每单都用全套步骤 |
| 5 少量现实确认 | 信息仍不确定时，许宁等外围人员确认公共区域活动 / 人物身份 | 梁发执行邮件、有限照片 / 工作回复、执行费用 | 非专业团队，可能跟丢、拍糊、判断错；不保证精确家庭住址，不新建外围人物支线 |
| 6 汇总交付 | 梁整合“寻访结果 / 联系线索摘要”，交最近区域、工作 / 活动范围、公开可确认联系方式、目击时间、是否仍在城市等 | 客户收到的结果摘要和相邻邮件 | 各单精度不同；交付的是定位 / 联系线索，不承诺绑架或抓回，也不保证位置长期有效 |
| 7 收费与结算 | 可有前期费 / 定金、交付后尾款及额外现实确认成本；产生付款确认和争议 | 客户凭证、付款上下文、结算 / 争议邮件 | 支付工具、金额和费率仍为年代变量。收费可跨前述阶段，不限定所有钱都在最后支付 |

## B. 客户服务费与外围费用

- **客户→梁**：购买寻访服务，可能分前期费用和尾款；凭证需与委托、收款确认和交付上下文关联，单凭转账不证明用途。
- **梁→许宁**：执行费用 / 报销，备注可能只有交通、资料、跑腿，不是客户付给梁的全部服务费，也不等于每次都完成定位。
- 不锁定具体支付平台、账户、金额、退款或最终尾款处理结果；同一任务的两条资金关系分别核验，不将二者合成一笔。

## C. 稳定编号与有限内部载体

正式格式为`S-XXX`。本文用`S-034`指周启明完整样本，数值仍可统一调整；许宁自身旧案记为设计占位`S_XU`，第三样本为`S_OTHER`，它们最终均对应不同的S编号。`S-031 / S-037`仍只是示例，不锁给具体人。业务编号和照片037是独立体系，不能用同号认定同一事件。

**S仅指收费客户任务。**王曼是事故后梁发现资料外传才建立的`R-XXX`内部风险确认 / 处置对象，不是付费委托目标；038～043归R，不参与收费样本或S数量。R记录至少有创建时间、王曼代号、状态、少量处理备注，具体编号可调。游戏既有`R01`～`R05`是关系ID，与风险任务编号不同。

- S编号出现在执行邮件、部分客户邮件、内部文件名、最终交付材料；公开寻人帖未必带编号，须靠目标姓名 / 昵称、旧照、公开来源和时间核对，而非强加公开编号。
- 梁使用普通**任务目录 + 轻量工作表 + 邮件**。每个S目录可放客户资料、公开搜索结果、目击、少量现实确认图、最终摘要；最终恢复范围不等于全部目录。
- 轻量登记表只记S编号、简短目标代号、当前阶段、收款状态、是否交付，不写完整客户违法叙述。
- 许宁长期执行期间曾收到梁发送的“本周任务安排 / 任务交接表”附件，包含一小段时期的登记表导出 / 截图。用途是告知哪些需确认、取消或待补材料，她保存旧附件。只给必要代号 / 状态，梁认为风险可控；不能把它设计成完整业务历史泄露。
- 导出行的编号、短代号、阶段用于对照邮件与其他来源。具体附件名、列布局、哪些行最终保留仍待细化，不默认其中含王曼事故后的风险任务。

## D. 梁为何保留记录

1. **运营**：多单需要对应客户 / 目标、已付多少、当前阶段、外围参与与是否交付；有限记录使任务能继续处理，不是完整数据库。
2. **纠纷**：客户可能拒付、质疑结果、要求退款或反过来威胁梁，委托、付款、交付记录能支持追款和答辩。周启明尾款纠纷是可核样本，不额外写发生过的退款事件。
3. **相互制约**：部分客户知道“家人失踪 / 朋友失联”叙述不完整或不实，梁保留部分委托记录可防止其完全否认关系。首先是现实业务需要和控制欲，不是为了收藏犯罪证据而保留所有资料。

## E. S-034：周启明客户侧相对完整样本

### 身份、动机与相对时间

“周启明”为可更名工作名：普通成年男性，与目标存在商业 / 债务纠纷，既不是正义举报者，也不是王曼朋友。王曼调查的几个月前，他经转介绍委托寻找主动与他断联的旧商业合作对象。此单不涉及绑架或杀人；不命名目标、不补写债务数额或其他人物剧情。

梁交付的位置部分准确但很快失效，周认为价格过高，拒付部分尾款。双方邮件争执，他保存证据为证明已付款、防止继续追款，而非为举报。结果有效一时与后续失效并存，不能据纠纷写成梁完全没有完成服务；未锁定最终尾款处理。

### 王曼如何找到他并取得材料

许宁保存的S-034执行邮件只有编号、目标信息和部分要求，**不显示客户身份**。王曼沿目标→对应公开寻人历史页的联系人“周先生”及当时普通联系方式→旧商业主页 / 公开联系资料→周启明；具体联系方式、网页地址与字段为占位。不黑电脑、不让许宁突然知道客户。

公开联系人只能提供候选，**不能直接证明他是客户**。周确认曾委托梁，并允许王曼扫描 / 复制自存邮件、付款凭证、结果和争议邮件作为采访核查材料；以一致目标 / 编号 / 时间核验。王曼记录取得日期、提供者、原来源及哪些为周副本 / 哪些为公开恢复，加入必要备份。玩家后来从记者工作页历史目录回看，不发起现实联络。

### 七段交易链

| 段 | 材料与创建 / 持有端 | 核验点 | 单独不证明 |
| --- | --- | --- | --- |
| 1 委托 | 周初次邮件，称旧合作对象失联，把商业纠纷说得较轻；周保留发件副本 | 目标、旧照 / 曾活动区域、关系与动机叙述 | 客户所有叙述真实、收费或完成 |
| 2 接单 | 梁回复已启动“特殊寻访 / 特殊单”，给S-034；周持收件副本 | 委托目标、邮件往返与编号相连 | 已付款、已经定位或交付 |
| 3 付款 | 周的付款 / 汇款凭证，配相邻邮件与确认 | 付款参与方对应梁、用途和该单相连 | 凭证单独证明服务用途、总价或全部收入 |
| 4 公开寻人及目击 | 页面使用表面正常失联理由；善意网友留下若干目击 | 同一目标、照片、时间与目击来源 | 发帖者动机、网友参与灰色业务；每条目击必真 |

| 6 交付 | 周收到含S-034的“寻访结果 / 联系线索摘要”，梁整合来源 | 目标、内部编号、目击 / 区域、有限现实确认与客户收件对应 | 对全部实时住址精准掌握、未来位置有效、全部任务都成功 |
| 7 尾款争议 | 周称位置很快失效、价格过高而拒付部分尾款；梁按约要求付 | 服务关系、已付与未付区分、结果交付后的纠纷 | 剩余尾款已付、退款成功或最终司法处理 |

七段来自客户持有往来、执行者持有工作材料、公开网页 / 网友记录及付款凭证，相互校验。客户一人保存的多封邮件不是多个独立证人的票数；邮件编号能串联，但编号本身不是交易完成证明。

## F. 许宁自身旧案：有严重后果的部分样本

- 在她成为外围执行者之前，控制型前男友直接联系回声相关渠道，称许宁精神 / 情绪异常且失联；随后出现公开寻人、目击和位置被找到，继而发生已锁定暴力。
- 可恢复范围锁定四类：A许宁自己的旧通信 / 设备备份；B前男友发给她的威胁信息中透露“花钱找人” / 使用相关寻访服务（不写反派完整自白）；C梁后来与她交流明确提及“你前男友那一单”；D一个不完整收费 / 付款确认片段。A是保存来源容器，B / C / D须分别保留创建者与实际时间，不能将同一备份算作四个独立证人。
- 四类与公开寻人 / 被找到记录共同支持她曾为S收费目标；没有前男友完整账户、完整委托邮件或完整结果包。D在许宁自存通信 / 备份中的具体原始发送方、片段形态与取得位置仍须细化，不能用一句“她后来取得”略过。
- 对照她自己的公开寻人、实际活动 / 位置变化和已有受暴力事实来源，确认与特殊寻访相关。客户付款材料不完整，不还原全部金额、全部聊天或客户完整包。
- 它主要证明机制可造成严重现实后果，以及另一笔收费关系存在；不能自动将所有特殊单推成绑架、杀人，或仅靠收费片段证明全部暴力因果。

## G. 第三个部分样本：普通灰色关系特殊单

本轮采用**寻找主动断联的成年家庭成员**方向，只保留角色关系，不起新姓名、不写长篇家庭剧情。它与许宁旧案、S-034处于不同时间，具体日期和S编号为变量。

只恢复不同S编号、一封部分任务邮件、公开寻人历史页、若干网友目击、一条**交付痕迹**及AT-62的一行交接表。邮件 / 表由许宁经手保存，公开页与目击由公开来源恢复；交付痕迹的具体文件形式、原保管人与许可副本流转仍须细化。缺完整客户付款、完整委托沟通及完整结果包，不增加此单暴力结局。

它支持S-034并非唯一、同一结构跨时期重复；其交付痕迹不独证收费目的，不能把这个部分样本当作第二份完整客户交易。

## H. 客户侧证据与来源核验

- 周提供的初次委托、接单确认、付款、结果和尾款争议互相对应；核对完整上下文、目标、时间、收发端和付款参与方，不凭一个显示名认定梁。
- 周的动机来自纠纷，说明可能偏向自己；将“价格过高 / 位置失效”的主观评价，与确实付款、确实收到结果等客观对应分开。
- 不把周公开转发等同客户证明，不让他提供其他客户完整材料或梁全部工作目录；只保存他实际持有且愿意提供的副本。

## I. 执行端证据与表格来源

许宁提供多封经手任务邮件、小额费用和旧交接附件。S-034邮件串到周持有的客户侧材料，旧表局部串到不同时期其他邮件。表格仅一段时期，不能要求它覆盖三单全部年代或自动包含许宁当年作为目标的旧单。

有限代号与状态解释梁为何敢发：单看只是工作安排，和客户邮件、公开页、付款、执行邮件合起来才出现业务意义。许宁不持有完整客户库、完整财务账或所有交易原件。

## J. 公开网页与现实活动证据

- S-034公开寻人历史页与网友目击，与执行邮件 / 结果中的同一目标、照片、区域、相对时间匹配；可证明信息被用于定位，不只证明页面存在。
- 保留目标当时仍有普通活动、主动断联与表面失联叙述的区别；具体活动来源以后细化，不虚构正式工作单位、住址或日历值。
- 许宁旧案和第三样本同样保留公开页、实际活动 / 位置基准与对应任务材料；普通网友不知背景，不能把善意回复等同共谋。
- **刘佳 / 赵妍仍是模式证据**：提前寻人异常与已证实机制高度一致，未新增她们属于具体收费特殊单的事实。它们既不是三个业务样本的替代，也不因异常自动匹配S编号。

## K. 交付与跨时期重复的证明

S-034客户收件结果包含编号及定位 / 联系线索摘要，交付后争议能进一步核验服务关系；部分准确但很快失效不改变曾交付事实。交付摘要须能回指公开目击与有限确认，不能一份文件写出全案答案。

许宁旧案有先被找到的后果和部分收费关联；第三样本有另一个时期的邮件 / 公开页 / 交付痕迹；旧交接表显示有限时期的同一管理结构。最终以**不同任务、不同时间、同一工作体系**支持持续性，不能只凭顺序数字或三封同单邮件。

相对关系：许宁先为目标，后来执行S-034；周使用服务在王曼调查前几个月。第三样本时间与两者不同，但不在本轮指定它落在哪个月。编号递增不作为唯一时间轴。

日期依据必须取自许宁旧通信、S-034邮件 / 付款 / 收件交付、第三样本邮件 / 公开页、交接附件收到时间，至少横跨不同月份 / 时段。先以`t_xu_old`、`t_s034_request/pay/delivery`、`t_other`、`t_handover_received`设计变量约束，最终日历未锁定。收到附件时间、表中任务日期和存档抓取时间分开；R记录 / 王曼六图不得加入此连续性样本。
