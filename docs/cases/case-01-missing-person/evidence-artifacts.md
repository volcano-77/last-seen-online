# 《寻人启事》证据载体清单

> 开发设计资料，玩家不可见。剧情以 [story-bible.md](story-bible.md) 为准，证明依赖见 [information-dependency-map.md](information-dependency-map.md)。本清单追踪证据为什么存在、由谁保管、如何到达玩家，不新增代码、JSON、UI或谜题。

## 1. 使用规则

- `AT-01`～`AT-50`为本文载体编号，不是Case新事实或谜题ID。50项中有合集、子项、原始来源和派生副本；038—043各图、037原件与预览、民事摘要中的时序子项、任务邮件中的编号，**不能当成互相独立的证明票数**。
- “已实现”只指当前phase-01已有载体与访问能力；“已设计、未实现”表示本轮锁定了来源或路径；“未设计载体”必须保留明确空白。当前实际导航仍以 [phase-01-reachability.md](phase-01-reachability.md) 为准。
- 只把创建者写到canon可确认的程度。网页发布者不一定是原照片拍摄者；梁聚合材料不等于六张全部由他拍摄；系统记录不等于记录中出现的人亲自制作文件。
- “最初持有人”区分原始载体、公开服务和后来副本。王曼许可取得照相馆副本，后经合作保存许宁经手材料；玩家从南城搜索旧工作页索引→失效地址→网页存档恢复网络资料目录。不能改成编辑交U盘、黑入电脑或遗物发现，不默认三种备份内容完全相同。
- 来源图的拍摄 / 网页发表时间、材料截图 / 组装 / 导出时间、复制 / 文件创建时间、任务创建时间分别核对。文件编号或可变属性不单独证明全部时序。
- 无任何长篇玩家自由输入要求；后续可用短搜索、普通来源链接、详情、缓存恢复与证据组合。未确定的人名、地址、日期、年龄、目录名、软件名不补写。
